A maintenance release. Nothing renders differently — the one change to a rule
substitutes a token for the literal it already resolved to. What this release
actually ships is a `theme.css` whose comments no longer describe a version of
the project that has been left behind.

## What changed

**Two print colours now reference their tokens.** The print block defines a
full paper palette, then two rules below it restated values from it as
literals: `color: #6c6c80` where `--text-faint` holds that value, and
`border: 1px solid #a8a8bc` where `--background-modifier-border` does — both
declared eighty lines above, in the same `@media print` block. Retuning the
palette moved one and left the other behind.

They were also invisible to `scripts/check-contrast.js`, which resolves tokens
and says in its own header that an inline colour needs a human. Two of the
print palette's values sat outside the only automated check that palette has.

**Comments that had drifted are corrected.** `theme.css` is the only file an
installed copy carries, so its comments are the documentation most users would
ever read, and several described a state the project had moved past — most
visibly a size budget reserving room for a Style Settings block that shipped
in 0.2.0.

**Two decisions are now written down where they are made.** A repeated
selector predicate in the task-state rules looks like something to compress
and is not: the child combinators keep a parent task from restyling a nested
sublist's checkbox, and the expanded `:not()` chain avoids exactly the class of
partially-supported feature that 0.2.1 was cut to clear. Separately, the
control-border rule styles `input[type="password"]` and `input[type="email"]`,
which look speculative in a note-taking app; they are the account login form
and the encrypted-vault unlock, and dropping them would hand a masked field a
1.39:1 border.

## What this costs you

Nothing, and this one is provable rather than argued. With comments stripped,
`theme.css` at 0.2.2 differs from 0.2.1 in exactly two places, and both
substitute a token for the literal value that token holds. No selector, rule
or declaration moved.

If you are on 0.2.1 and everything looks right, it still will. If you are
happy where you are, there is nothing here you need.

## Install

Download `theme.css` and `manifest.json` below into
`YourVault/.obsidian/themes/Neonflux/`, then Settings → Appearance → Themes.

Already installed from the community list? Obsidian updates it for you.
