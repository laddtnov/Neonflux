The theme bends to your reading, and stops breaking on paper and in
high-contrast mode.

**Nothing changes by default.** Every colour, heading and code block renders
exactly as it did in 0.1.1. What is new is either opt-in, or only appears in a
context the theme previously ignored — printing, high-contrast mode, and task
lists that use more than done/not-done.

## Five switches, with Style Settings

Install the [Style Settings][ss] plugin and Neonflux gains a panel. Each switch
gives back a trade-off this theme makes on purpose:

- **Turn off heading glow.** The text-shadow on `h1` and `h2`.
- **Turn off uppercase headings.** The tracked caps are the genre's signature
  and measurably slower to read. Worth turning off in a narrow column.
- **Use the system font for body text.** Rajdhani is a condensed display face
  with a low x-height doing a text face's job. This hands prose back to your
  system's reading font and keeps Orbitron on the headings.
- **Turn off the `>_` prefix.** It is generated content, so screen readers
  announce it before every top-level heading in your vault.
- **Turn off task state colours.** The characters stay, the accents go.

Every one is an opt-*out*, which is deliberate: a switch that defaulted to on
would have to apply itself by default, and the feature would then only work
for people who have the plugin. Without it, the theme is exactly as it ships.

[ss]: https://github.com/mgmeyers/obsidian-style-settings

## Task states beyond done

If your vault tracks things, the community convention encodes state in the
checkbox — `- [/]`, `- [>]`, `- [-]`. Obsidian treats every one of those as
checked, so until now they all rendered as the same cyan tick: a task under
review looked identical to a finished one.

| Type | State | Looks like |
| --- | --- | --- |
| `- [+]` | Found | cyan box, `+` |
| `- [?]` | Reviewing | blue box, `?` |
| `- [/]` | Testing | yellow box, `/` |
| `- [x]` | Done | green tick, struck through |
| `- [>]` | Waiting | grey box, `>` |
| `- [-]` | Rejected | pink box, `-`, struck through |

They are drawn as the literal character in the monospace face rather than as
emoji or icons — so a status column stays aligned, the colours come from the
palette rather than from your font vendor, and the download does not grow.

Waiting is the one state without an accent, because nothing is happening to
it. Callout icons also moved to the machined end of the icon set — a terminal
for `note`, a circuit board for `info`, a scanner for `question`.

## Printing no longer wastes a cartridge

Exporting a note to PDF used to lay the light palette's page colour down as
ink, edge to edge on every sheet, with callouts printing as solid blocks and
the accents arriving as a set of near-identical greys on a mono printer.

Print now collapses to one paper palette: white page, near-black ink, no glow,
fills replaced by hairlines. The type stays — the faces are what make an export
recognisably Neonflux, and they print fine.

Two things about Obsidian's export are worth knowing, because both are the
opposite of the obvious assumption. **Export to PDF always renders light**,
whichever scheme you are in — it switches before it renders. And print
backgrounds are **not** dropped by the driver: Obsidian explicitly instructs it
to reproduce every fill, which is why the page colour was reaching paper.

## High-contrast mode works

In forced-colors mode the OS replaces the palette and the theme gets out of
the way, which is correct. Two things were broken there and are fixed:

- **Callouts disappeared completely.** Not just their tint — the title, the
  body text and the border rendered as blank page. Obsidian composites
  callouts with a blend mode, blend modes are not reset by forced colors, and
  blending black text over a white backdrop produces white.
- **A finished task looked unfinished.** The tick is drawn as a coloured
  shape, so it flattened to the page colour and every checkbox read as empty.

Callouts, code blocks and tag chips now carry real borders, since anything
drawn only with a background disappears when every background becomes the same
colour.

There is also support for `prefers-contrast: more`. Ask your OS for more
contrast and the muted text, faint text and control borders move up — from a
range of about 3:1–7:1 to about 7.5:1–12:1. The neon accents are already past
12:1 and are left alone, since raising them would change the theme rather than
fix a problem.

## A larger file, and not because of fonts

`theme.css` goes from **124KB to 152KB**. All of it is stylesheet: the embedded
font payload has not moved from 103KB since 0.1.1, and no font was added or
changed. CI now fails the build if either number drifts past its budget, which
is how this stayed visible rather than being discovered in a review.

## Install

Download `theme.css` and `manifest.json` below into
`YourVault/.obsidian/themes/Neonflux/`, then Settings → Appearance → Themes.

Already installed from the community list? Obsidian updates it for you.
